# Award camera feasibility — 2026-11-18

Source-only brainstorming spike. **Recommendation:** retain the orthographic Thailand scene; clicking an award should recenter and zoom its province-derived position, then emphasize its badge. This reuses existing travel without requiring a rendering rewrite. Everything labelled proposal below requires later approval. No application, tests, server, browser, installation or commit was run for this research.

**Implemented foundation.** The default contract calls medals decorative, explicitly excluding earned ranks ([Project.md:43](<D:/Projects/Hamsterhub/Map Project Showcase/Project.md:43>)). Preview callbacks are no-ops; scene-local clicks toggle `selectedPinId`/`aria-pressed`, while individual handlers only call `onSelect` ([MapPreview.tsx:34](<D:/Projects/Hamsterhub/Map Project Showcase/src/ui/MapPreview.tsx:34>); [ThailandMap.tsx:277](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:277>), [ThailandMap.tsx:290](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:290>)). Explorer selection instead opens a card through parent state ([App.tsx:223](<D:/Projects/Hamsterhub/Map Project Showcase/src/App.tsx:223>), [App.tsx:380](<D:/Projects/Hamsterhub/Map Project Showcase/src/App.tsx:380>)). Individual-award camera travel is therefore missing.

The reusable `moveCamera(position,target,zoom,animate)` cancels preceding travel, interpolates position/target/zoom with cubic ease-out over 240ms, updates projection and redraws. Cluster activation already translates camera and target together toward member positions and multiplies zoom by 1.85, capped at eight; zoom/reset controls share this function ([ThailandMap.tsx:158](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:158>), [ThailandMap.tsx:363](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:363>), [ThailandMap.tsx:541](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:541>)).

**Missing award contract and presentation.** Neither `Kid` nor `Project` contains awards, and `prepareKids` reconstructs explicit fields, so adding metadata upstream alone would discard it ([types.ts:16](<D:/Projects/Hamsterhub/Map Project Showcase/src/types.ts:16>); [prepareKids.ts:33](<D:/Projects/Hamsterhub/Map Project Showcase/src/data/prepareKids.ts:33>)). Gold/Silver/Bronze eligibility, trophy meaning, owner/project association and multiple-award identity remain product decisions. Proposed: approved metadata with stable award identity, accessible textual distinction and explicit null handling; never infer achievements from province or array order. Preserve the three-student default; demonstrate additional variants through explicit fixtures.

For visual impact, **proposed first option** is four distinct DOM badge treatments plus targeted travel and selection emphasis. Current badges already use gold CSS, ribbons and stars. Actual 3D trophies would require geometry/material/instancing work; a perspective cinematic camera would additionally require new framing and overlay regression work. Both are larger alternatives ([styles.css:318](<D:/Projects/Hamsterhub/Map Project Showcase/src/styles.css:318>); [ThailandMap.tsx:131](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:131>)).

**Orthographic consequences.** Camera zoom is bounded to 1–8; moving closer alone does not enlarge objects. Three.js divides frustum dimensions by zoom ([ThailandMap.tsx:42](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:42>); [OrthographicCamera.js:195](<D:/Projects/Hamsterhub/Map Project Showcase/node_modules/three/src/cameras/OrthographicCamera.js:195>)). Preview resize uses half-height `max(7.6,4.2/aspect)`, so equal zoom produces different framing on narrow screens ([ThailandMap.tsx:467](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:467>)). Proposed framing should use current frustum, viewport padding and label/control clearance, with bounded zoom. Translate camera and target together to retain orientation. Explicitly enforce target bounds: the gesture clamp is bypassed while `movingCamera` is true ([ThailandMap.tsx:424](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:424>)).

Projection is local equirectangular, with origin 101°E/13°N; scene placement converts projected `(x,y)` into `(x,0.28,-y)` ([project.ts:8](<D:/Projects/Hamsterhub/Map Project Showcase/src/geo/project.ts:8>); [ThailandMap.tsx:504](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:504>)). Resolve the existing world position by ID, avoiding a second coordinate convention. Badges are fixed 40px DOM targets: camera zoom enlarges land and separates anchors, but does not magnify badge artwork ([ThailandMap.tsx:201](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:201>); [styles.css:292](<D:/Projects/Hamsterhub/Map Project Showcase/src/styles.css:292>)). Any badge enlargement needs a separate bounded treatment.

**Clustering and focus conflicts.** Projection feeds 36px connected-component clustering each draw. Max-zoom fan-out shows 24 members per page, spaced 42px; those offsets are temporary screen positions ([ThailandMap.tsx:214](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:214>), [ThailandMap.tsx:300](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:300>); [screen.ts:75](<D:/Projects/Hamsterhub/Map Project Showcase/src/cluster/screen.ts:75>)). Travel clears fan-out, so clicking a fanned award then moving can remove its button and regroup it. Proposed: travel toward the underlying anchor, retain selected identity, then reveal its page or a selected overlay if overlap persists. Never unproject the fan-out offset as location.

Current pending focus settles after cluster travel; removed focused buttons can fall back to the map host. Explorer card focus introduces another owner ([ThailandMap.tsx:384](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:384>); [PinCard.tsx:60](<D:/Projects/Hamsterhub/Map Project Showcase/src/ui/PinCard.tsx:60>)). Proposed coordination must prevent camera completion stealing modal focus and define repeat-click, Escape, filtering, reset and interruption behavior.

**Privacy, motion and limits.** Resolve awards only against prepared visible students: strict opt-in and deterministic, containment-checked province jitter already exist ([prepareKids.ts:27](<D:/Projects/Hamsterhub/Map Project Showcase/src/data/prepareKids.ts:27>); [provinces.ts:243](<D:/Projects/Hamsterhub/Map Project Showcase/src/geo/provinces.ts:243>)). Camera framing must preserve those placements and list fallback. Existing travel skips animation under reduced motion; gestures cancel it, visibility/resize/preference changes finish it, and filtering stops it. Keyboard camera actions are immediate. “Pause sparkles” controls decoration separately ([ThailandMap.tsx:174](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:174>), [ThailandMap.tsx:438](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:438>), [ThailandMap.tsx:493](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:493>); [styles.css:420](<D:/Projects/Hamsterhub/Map Project Showcase/src/styles.css:420>)).

Rendering uses dirty frames, capped pixel ratio and only 30 ambient markers, but travel still projects, clusters and updates DOM each frame; dense neighbor comparisons can grow quadratically ([ThailandMap.tsx:44](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:44>), [ThailandMap.tsx:195](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:195>), [ThailandMap.tsx:268](<D:/Projects/Hamsterhub/Map Project Showcase/src/scene/ThailandMap.tsx:268>); [screen.ts:33](<D:/Projects/Hamsterhub/Map Project Showcase/src/cluster/screen.ts:33>)). Preserve these budgets; avoid continuous cinematic loops. FPS/load targets remain provisional ([Project.md:162](<D:/Projects/Hamsterhub/Map Project Showcase/Project.md:162>)).
